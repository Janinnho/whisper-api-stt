Setup Guides

Microsoft Entra ID (Azure AD) Setup

1. Create App Registration

  1. Go to Azure Portal → Microsoft Entra ID
  2. Navigate to App registrations → New registration
  3. Enter a name (e.g., "Whisper Transcription")
  4. Select Accounts in this organizational directory only (or multi-tenant if needed)
  5. Under Redirect URI:
    • Select Web as platform
    • Enter:
  6. Click Register

2. Configure Authentication

  1. In your app registration, go to Authentication
  2. Under Platform configurations, verify the redirect URI is correct
  3. Scroll down to Advanced settings
  4. Set Allow public client flows to Yes (enables PKCE without secret)
  5. Click Save

3. API Permissions

  1. Go to API permissions
  2. Click Add a permission → Microsoft Graph → Delegated permissions
  3. Add these permissions:
    • openid (usually pre-added)
    • profile
    • email
  4. Click Grant admin consent (if you have admin rights)

4. Copy Configuration Values

Go to Overview and copy these values to the Settings tab:

Azure Portal Field Settings Field
Application (client) ID OIDC Client ID
Directory (tenant) ID Use in Discovery URL (see below)

5. Discovery URL Format

Replace {tenant-id} with your Directory (tenant) ID:

https://login.microsoftonline.com/{tenant-id}/v2.0/.well-known/openid-configuration

Example: https://login.microsoftonline.com/12345678-1234-1234-1234-123456789abc/v2.0/.well-known/openid-configuration

6. Optional: Client Secret

A client secret is not required if you enabled public client flows (Step 2). This app uses PKCE for security.

If you prefer using a secret:

  1. Go to Certificates & secrets
  2. Click New client secret
  3. Copy the Value (not the Secret ID!) immediately
  4. Paste it in the OIDC Client Secret field
Tip: Test your Discovery URL by opening it in a browser. You should see a JSON response with endpoints.

Required Scopes

This application requests the following scopes:

  • openid - Required for OIDC
  • profile - User's name
  • email - User's email address

User Claims

The following claims are read from the ID token:

  • sub - Unique user identifier (required)
  • email or preferred_username or upn - User's email
  • name or given_name - Display name

API Usage

OpenAI-Compatible API

This application provides an OpenAI-compatible transcription API at:

Example Request (cURL)

curl -X POST "" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: multipart/form-data" \
  -F "file=@audio.mp3" \
  -F "model=whisper-1"

Example Request (Python)

from openai import OpenAI

client = OpenAI(
    api_key="YOUR_API_KEY",
    base_url=""
)

with open("audio.mp3", "rb") as audio_file:
    transcript = client.audio.transcriptions.create(
        model="whisper-1",
        file=audio_file
    )
    print(transcript.text)

Supported Parameters

Parameter Description
file Audio file (mp3, wav, m4a, etc.)
model Model name (whisper-1 for cloud, or tiny/base/small/medium/large for local)
language Optional language code (e.g., "en", "de")
response_format text, json, verbose_json, srt, vtt
